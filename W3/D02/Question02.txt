1.因为残差add相差要求分辨率和通道数一致，concat只要求分辨率一致。而且残差相加也不是任意特征都可以。残差的目的
是保证在深层网络中模型效果不会退化，所以其中一个要求是上层模型的输出，这样再算梯度时至少也大于1，不会比原有的差

批改：7/15。形状对齐的判断正确，但残差连接不保证梯度大于1，也不保证效果一定不下降。
标准答案：
残差块把同一输入经过主分支得到的F(x)，与捷径分支的x或投影后的P(x)相加。
两条分支应具有设计上的对应关系，并使batch、通道、高、宽匹配，不能任意拿两个特征直接相加。
捷径提供直接的信息和梯度传播路径，有助于深层网络优化，但不是性能保证。
例如标量y=x+F(x)的导数是1+F'(x)，当F'(x)=-1时导数为0，所以“梯度至少大于1”不成立。
补充：concat要求除拼接轴外的其他维度一致，不是只要求分辨率一致。

常用方案是把[4,8,16,16]投影为[4,16,8,8]，再与另一条分支相加：

aligned = projection(x)  # 此时x形状为[4,16,8,8]。
题目只需要给出一种有效方案。kernel_size=1、stride=2的转置卷积会把8变成15，不能直接用于这里的向上对齐。

3.先检查是否处在model.eval()下，只有在评估模式下，BN层才会直接使用已有的BN层参数不会做更新。在model.train()
下，即使冻结参数，也只会不改变模型权重参数，但是BN层依然会继续计算更新。

批改：18/20。主要判断正确，但需要把“BN层参数”与“运行统计buffer”区分清楚。
标准答案：
冻结参数只阻止可学习参数更新，不会自动冻结BN的running_mean、running_var和num_batches_tracked。
默认BN在train模式下，前向计算就会更新这些buffer，即使使用torch.no_grad()也会更新。

标准答案：
BN2d对每个通道在batch和空间位置上估计均值、方差，也就是统计N×H×W个值。
小batch可能使统计不稳定或缺乏代表性；如果高光谱patch相邻、重叠，样本高度相关，也要谨慎解释统计结果。
因此，不能仅凭某一次验证准确率断言BN有效或无效。
应固定数据划分和其他设置，比较不同batch下的运行统计及训练、验证表现，记录重复实验的波动。
小batch不必然使BN失效，还要看空间尺寸和数据相关性；波段多、存在噪声也不等于BN一定不好。

6. W03-D02-Q06（补充题，不计入原100分）

题目：参数与buffer有什么区别？结合卷积层和BN层，说明它们在创建模型时如何产生、训练时如何更新、如何保存和加载，以及重载后在训练和推理中分别起什么作用。

参考答案：

（1）分别是什么，如何产生？
参数是模型用于学习的数值，例如卷积层的weight、bias，以及BN的缩放weight和偏移bias。
创建nn.Conv2d或nn.BatchNorm2d时，这些参数会自动建立并初始化，不是训练之后才产生。

buffer是登记在模型中、但不作为可学习参数的张量状态。默认BN会自动建立：
running_mean：运行均值，初始为0。
running_var：运行方差，初始为1。
num_batches_tracked：经过的训练批次数，初始为0。

buffer不是BN专属，也可以用register_buffer自行登记。普通Conv2d默认没有buffer，但有参数；没有buffer不代表没有保存卷积权重。
这些内容起初保留在内存中的模型对象里，执行torch.save后才写入文件。

（2）训练时分别如何更新？
参数通常由loss.backward()计算梯度，再由optimizer.step()更新；只做前向计算不会更新普通卷积的权重。
默认BN在train模式下，用当前批次统计进行归一化，并在前向计算时更新运行统计和计数，不需要反向传播或optimizer.step()。
所以，冻结参数或使用torch.no_grad()，都不能单独阻止train模式下的BN统计更新。buffer是否更新、怎样更新，取决于对应模块的实现。

（3）如何查看、保存和加载？
model.named_parameters()：查看参数名称和张量。
model.named_buffers()：查看buffer名称和张量。
model.state_dict()：同时包含参数和需要保存的buffer；用persistent=False登记的buffer不在其中。
torch.load()：把文件读回内存。
new_model.load_state_dict()：把读回的参数和buffer一起恢复到结构匹配的新模型中，不需要另写一次buffer加载。

示例代码：
# 假设原model是ResicBlock(3, 4, use_1x1conv=True, strides=1, drop_rate=0.4)。
# 这段放在已有model的代码后；torch、Path和ResicBlock沿用D02.py中的定义。
save_path = Path(__file__).resolve().parent / "buffer_example.pth"
torch.save(model.state_dict(), save_path)

new_model = ResicBlock(3, 4, use_1x1conv=True, strides=1, drop_rate=0.4)
saved = torch.load(save_path, map_location="cpu", weights_only=True)
new_model.load_state_dict(saved)  # 同时恢复参数和buffer。

print("卷积权重恢复一致：", torch.equal(model.conv1.weight, new_model.conv1.weight))
print("BN运行均值恢复一致：", torch.equal(model.bn1.running_mean, new_model.bn1.running_mean))

new_model.eval()  # 模式要自己设置，不会随state_dict自动恢复。
data = torch.ones(2, 3, 4, 4)
with torch.no_grad():
    pred = new_model(data)
print("重载后输出形状：", pred.shape)

（4）在新模型中分别起什么作用？
参数：卷积权重负责计算特征，BN的weight和bias负责缩放、平移归一化后的特征；它们在训练和推理的前向计算中都会用到。
buffer：对于默认BN，eval模式下使用加载的运行均值和方差进行归一化，并保持统计不变；train模式下使用当前批次统计进行归一化，再从加载的运行统计和计数继续更新。
num_batches_tracked不是模型的epoch；它记录BN经过的训练批次数，在momentum=None时还影响运行统计的更新比例。

（5）为什么两类状态都要恢复？
若只恢复卷积等参数，没有正确恢复BN的运行统计，eval输出可能与保存前不同。
若想继续训练，还需要另行恢复优化器、epoch等状态；仅加载model.state_dict()不等于精确续训，也不会恢复requires_grad冻结设置。

记忆句：参数负责学习，buffer保留非学习状态；load_state_dict一起恢复它们，前向计算按模块和模式使用它们。
